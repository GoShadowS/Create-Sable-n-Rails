# Create: Sable 'n' Rails

**Неофициальный экспериментальный аддон**, добавляющий серверно-авторитетный слой интерактивности для
контрапций Create, которые движутся как sub-levels Sable. Это не официальный порт Create: Interactive, и
проект не одобрен командами Create, Create: Interactive или Sable. Valkyrien Skies ship objects не
используются, зависимости от Valkyrien Skies нет.

## Целевая платформа

- Minecraft **1.21.1**, Java **21**, только **NeoForge** (без Fabric и Forge).
- Зафиксированные версии зависимостей: NeoForge `21.1.228`, Create `6.0.10-280`, Sable `2.0.6`,
  Ponder `1.0.82`, Flywheel `1.0.6`, Registrate `MC1.21-1.3.0+67`, Sable Companion `1.6.0`
  (транзитивно, в JAR не включается).
- Каждый используемый API сверен с исходниками именно этих версий Create и Sable; доказательства — в
  [UPSTREAM_RESEARCH.md](./UPSTREAM_RESEARCH.md).

## Состояние

### Реализовано

- **Маркеры Interact Me / Interact Me Not** (`create_sable_n_rails:interact_me`,
  `create_sable_n_rails:interact_me_not`): мгновенно ломающиеся, с поддержкой воды, крепятся на пол, потолок
  и стену, с оригинальными текстурами, рецептами (андeзитовый сплав и шестерня Create), loot table и
  advancement для разблокировки рецепта.
- **Шесть серверных политик** — по одной на категорию контрапции (поезда, поступательные, подшипники,
  часовые, на тележке, прочие), каждая со значениями `ALWAYS` / `WITHOUT_STICKER` / `WITH_STICKER` /
  `NEVER`. По умолчанию: `WITH_STICKER` для пяти известных категорий, `NEVER` для неизвестных контрапций
  других модов.
- **Серверная проверка** для любого правого клика по блокам движущейся контрапции: инвентари/хранилища,
  сиденья, гаечный ключ и поведения акторов идут через один и тот же метод, поэтому отклонённое
  взаимодействие игнорируется сервером, даже если изменённый клиент всё равно отправит пакет. Сиденья и
  ключ блокируются осознанно — см. «Детали проверки» ниже про один клиентский побочный эффект.
- **Клиентское отражение** решения: контрапция без единого интерактивного блока пропускается клиентским
  raytrace взаимодействия, поэтому взгляд на неё ведёт себя как взгляд мимо (предмет в руке продолжает
  работать), а не «съедает» нажатие.
- **Сохранение через собственные данные Create**: маркеры — обычные блоки контрапции, поэтому состояние
  переживает разборку, повторную сборку, перезагрузку чанков и сохранение/загрузку мира без отдельного NBT.
- **Актуальность после изменений**: решение пересчитывается при изменении карты блоков контрапции — покрыты
  все три пути записи Create, включая переопределение в вагоне, которое не вызывает `super`, и клиентский
  пакет изменения блока — а также при старте/остановке мира и загрузке/перезагрузке конфигурации. Запись
  кэша переиспользуется только если совпадают точная сигнатура маркеров (позиция и вид маркера, сравнение
  структурное, а не по хешу), категория контрапции и фактически выбранная политика конфигурации, поэтому
  замена одного маркера на другой в той же позиции не может оставить устаревшее решение.
- **Индикатор заблокированной контрапции в HUD** (только клиент): пока прицел наведён на контрапцию, которую
  политика запрещает, над хотбаром выводится одна строка о том, что взаимодействие заблокировано. Он отвечает
  на вопрос «почему клик ничего не сделал», никогда не появляется для разрешённой контрапции и скрывается по
  F1 и в режиме наблюдателя. Решение берётся из того же метода политики, что и у шлюза взаимодействия,
  поэтому индикатор не может противоречить серверу; собственных полномочий у него нет. Для поиска цели
  используется собственный клиентский raytrace Create — `getRayInputs` для ограниченного дальностью луча и
  `rayTraceContraption` для реальных форм блоков — по реестру загруженных контрапций Create. Пересечение
  bounding box является только предварительным фильтром и никогда не считается попаданием, поэтому
  контрапция, которую луч задевает по габаритам, но не попадает внутрь, индикатор не включает.
- Gradle-проект Java 21 / NeoForge, метаданные мода, конфигурация mixin, задачи `runClient` / `runServer` /
  `gameTestServer`, JUnit-тесты чистой логики решения и GameTests.

### Экспериментально

- Весь слой интерактивности экспериментален: код написан и статически разобран, но **сборка Gradle, тесты
  и игровые проверки не выполнялись** в окружении разработки (см. «Проверки» ниже). Считайте функцию
  непроверенной, пока она не соберётся и не пройдёт ручной чек-лист.

### Запланировано

- Пересмотреть сход с рельсов / Train Buffer Stop, Propagator Bearings (включая disjointed) и передачу

  зафиксированных версий. В Create 6.0.10 и Sable 2.0.6 такого API не найдено.

### Не поддерживается

- Fabric и Forge.
- Интеграция Valkyrien Skies, VS2 ship objects и поведение Create: Interactive, привязанное к 1.20.1.
- Сход с рельсов, Train Buffer Stop, Propagator Bearings, изменения вложенных контрапций и передача через
  интерфейсы предметов/жидкостей. Они **не** реализованы, и код не делает вид, что это не так.
- Любые функции, не перечисленные в «Реализовано».

## Как это работает

| Часть | Поведение |
|---|---|
| Блоки-маркеры | Состояние маркера хранится в `Contraption#getBlocks()`; Create сам сериализует эту карту в NBT сущности контрапции и возвращает блоки в мир при разборке. Больше ничего решение не сохраняет. |
| Выбор политики | `ContraptionCategory` определяет категорию контрапции, затем применяется соответствующее значение серверной конфигурации. `ALWAYS`/`NEVER` игнорируют маркеры (побеждает настройка сервера); `WITHOUT_STICKER` — список запрета; `WITH_STICKER` — список разрешения. |
| Проверка | Один отменяемый `HEAD`-inject в `AbstractContraptionEntity#handlePlayerInteraction`. Возврат `false` — это собственный результат Create «не обработано»: доступ к хранилищу, посадка на сиденье, обработка ключом и поведения акторов не выполняются, вызов `sender.swing(...)` не достигается. |
| Клиентское отражение | `@Redirect` на единственный *вызов* `rayTraceContraption` внутри `rightClickingOnContraptionsGetsHandledLocally`: контрапция без интерактивных блоков пропускается циклом взаимодействия. Только косметика: решает сервер. |
| Пропуск при сборке | Маркеры объявляют себя перемещаемыми через `BlockMovementChecks.registerMovementAllowedCheck` (`SUCCESS` для двух маркеров, `PASS` для остального). Без этого `PushReaction.BLOCK` делает их «неперемещаемыми», и любая контрапция с маркером не собирается. |
| Сиденья и ключ | Блокируются так же, как всё остальное: ни посадки, ни переезда поезда на запрещённой контрапции. Переезд дополнительно блокируется там, где он действительно завершается — в `TrainRelocationPacket#handle` на сервере, — поэтому входа в клиентский режим недостаточно, чтобы сдвинуть запрещённый поезд. |
| Sable | Sable 2.0.6 уже обеспечивает физику, столкновения и raytrace в sub-levels для контрапций Create. Аддон это не дублирует и не создаёт ship objects. |

## Детали проверки

**Что отменяет запрет.** Проверка — отмена на `HEAD` в `AbstractContraptionEntity#handlePlayerInteraction`,
единственном методе, через который Create обрабатывает любой правый клик по блокам контрапции. Отмена
означает, что тело метода не выполняется: нет ни `contraption.interactors`, ни
`MountedStorageManager#handlePlayerStorageInteraction`, ни посадки, ни высадки пассажира. После этого
`ContraptionInteractionPacket#handle` не доходит до `sender.swing(...)`, потому что вызов защищён тем же
возвращаемым значением.

**Переезд гаечным ключом закрыт в трёх точках, а не в одной.** Возврат `false` из `handlePlayerInteraction`
на клиенте — это выбор ветки, а не остановка: он ведёт в `handleSpecialInteractions`, где ветка ключа на
вагоне вызывает `TrainRelocator#carriageWrenched` и включает режим переезда. Сам переезд запрашивается
позже отдельным `TrainRelocationPacket`, и его обработчик (`TrainRelocationPacket#handle`) — единственный
вызов `TrainRelocator#relocate(...)` во всём Create. Поэтому запрещённая контрапция останавливается на:
(1) проверке взаимодействия с контрапцией, (2) `handleSpecialInteractions` — режим переезда на клиенте не
включается, и (3) `TrainRelocationPacket#handle` — даже клиент, вошедший в режим (или изменённый клиент,
отправивший пакет напрямую), не завершит переезд. Разрешённые поезда идут штатным путём Create и
переезжают как раньше.

**Переезд оценивается по всему поезду, с обеих сторон.** `TrainRelocator#relocate` двигает *поезд*: он
проходит по `train.carriages` и меняет состояние всего поезда. Поезд — это список независимых вагонов, у
каждого своя `CarriageContraption`, своя карта блоков и свои маркеры, поэтому указание разрешённого вагона
не должно «отмывать» запрещённый. Правило живёт в одном методе
`ContraptionInteractionPolicy#isTrainInteractive(Train, Level)`, который вызывают и клиентская проверка
(`ContraptionHandlerClientMixin`, до `TrainRelocator#carriageWrenched`), и авторитетная серверная
(`TrainRelocationPacketMixin`) — разойтись они не могут.

| Ситуация | Клиент | Сервер |
|---|---|---|
| Все вагоны интерактивны | режим переезда включается | пакет принят, поезд перемещается |
| Хотя бы один вагон неинтерактивен | клик по **любому** вагону поезда не включает режим | пакет отклоняется, даже если отправлен |
| Изменённый клиент указывает разрешённый вагон поезда с запрещённым | (не участвует) | отклонено: оценивается весь поезд, а не указанный вагон |

**Поддельные и некорректные пакеты отклоняются до выполнения кода Create.** Оба идентификатора в
`TrainRelocationPacket` контролируются клиентом. Миксин отменяет обработку на `HEAD`, если `trainId` не
разрешается, если `entityId` не является вагоном, если этот вагон принадлежит другому поезду, или если
хотя бы один вагон поезда неинтерактивен. Первый случай — не только вопрос политики: обработчик Create
строит сообщение в лог из `train.id.toString()` внутри ветки `train == null`
(`TrainRelocationPacket.java:51-53`), поэтому неизвестный id, дошедший туда, — это `NullPointerException`
в серверном потоке, а не отказ. Отмена на `HEAD` означает, что эта строка не достигается.

**Крайний случай fail-closed и что это значит в игре.** Для каждого вагона контрапция находится через
`CarriageContraptionEntity`, зарегистрированную для нужного измерения. Если такой сущности **нет** —
например вагон многомерного поезда не загружен в вашем измерении или сущность вагона ещё не создана на
клиенте, — вагон считается **запрещённым**. Поэтому поезд, «разрешённый по конфигурации», не становится
перемещаемым автоматически: все вагоны должны быть ещё и загружены там, где выполняется проверка. На
практике обычный поезд в одном измерении переезжает нормально; поезд, часть которого в другом измерении,
будет отказывать в переезде, пока весь не окажется загружен в измерении проверяющего. Это сделано
осознанно (иначе нечего оценивать), и именно поэтому страница не утверждает, что разрешённый поезд можно
переместить всегда.

**Сиденья и ключ внутри проверки осознанно.** Create считает сиденье блочным взаимодействием, поэтому
исключение для сидений позволило бы садиться именно в те контрапции, которые сервер объявил
неинтерактивными — а для поездов это самый важный случай. То же рассуждение для ключа: переезд вагона и
есть взаимодействие с этим вагоном.

**Значение по умолчанию `otherHandling = "NEVER"` и что оно означает.** Любой тип контрапции, который
аддон не распознаёт (то есть добавленный другим модом), по умолчанию неинтерактивен: это сохраняет
поведение до 0.2.0 для таких контрапций, но означает, что «из коробки» нельзя открыть сундук на
контрапции неизвестного аддона. Пять известных категорий Create по умолчанию `WITH_STICKER`, то есть
неинтерактивны, пока не прикреплён маркер `interact_me`. Оба значения выбраны осознанно и не меняются
молча; чтобы вернуть безусловное взаимодействие, поставьте категории `ALWAYS`.

## Конфигурация

`config/create_sable_n_rails-common.toml` (пустая заглушка) и `config/create_sable_n_rails-server.toml`,
плюс копия на мир в `<world>/serverconfig/`. В серверном файле шесть значений:

```toml
[interactivity]
    otherHandling = "NEVER"
    trainHandling = "WITH_STICKER"
    translatingHandling = "WITH_STICKER"
    bearingHandling = "WITH_STICKER"
    clockworkHandling = "WITH_STICKER"
    mountedHandling = "WITH_STICKER"
```

NeoForge синхронизирует их клиентам; клиент не может выдать себе право взаимодействия.

## Установка

Проверенного релизного JAR пока нет. Когда он появится: установите одинаковые версии Minecraft 1.21.1
NeoForge, Create и Sable на **клиент и сервер**, затем положите JAR аддона в `mods/`. На сервере аддон
обязателен; на клиенте он нужен для клиентского отражения решения и моделей маркеров, поэтому ставить его
нужно на обе стороны.

## Сборка

При наличии JDK 21 и доступа к Maven Central, NeoForged Maven и Maven Create/Sable:

```bash
./gradlew build          # компиляция + jar
./gradlew test           # JUnit-тесты чистой логики политик
./gradlew runClient      # клиент для разработки
./gradlew runServer      # выделенный сервер для разработки
./gradlew gameTestServer # GameTests без графики
```
